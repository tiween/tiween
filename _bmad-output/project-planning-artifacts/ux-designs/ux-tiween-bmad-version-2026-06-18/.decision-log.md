## D1 — This is a B2B/internal surface, NOT the B2C identity

The existing `ux-tiween-bmad-version-2026-06-16` run (`status: final`) is the **B2C**
consumer identity: Gold Leaf × Aubergine, shadcn/ui + Tailwind v4, Next.js. It does
**not** apply here. Strapi admin plugins render inside the host admin and inherit the
**Strapi Design System v2** theme. This is a fresh Create run for a different surface.

## D2 — Stick to Strapi DS v2; DESIGN.md is a thin inheritance spine (user pick)

Ayoub: _"stick as much as possible to strapi DS."_ DESIGN.md therefore declares
inheritance from Strapi DS v2 and documents only the **deltas** the codebase actually
needs — it does NOT author a custom palette/typography. No Tiween brand layer is
applied to the admin. Rationale: a custom brand layer fights the host theme, breaks
on Strapi upgrades, and trips the `strapi-ui-reviewer` DS-conformance gate.

Deltas worth pinning:

- **Status badge token mapping** (semantic, not visual): `pending`→`warning`,
  `approved`→`success`, `suspended`→`danger`, undefined→`neutral`. Mirrors the
  existing `events-manager/StatusBadge`.
- **Icon set**: `@strapi/icons` only. Plugin menu icon = `Store` (already set).
- **Density / layout grid**: inherit `Layouts.Root` + `Grid.Root` 12-col; forms use
  `col={6} s={12}` two-up like the existing `VenueFormModal`.

## D3 — Coverage: all four 2D surfaces (user pick)

1. **Venues list + Venue form modal** (2D.2)
2. **Property authoring** — categories (hierarchical) + definitions (2D.3)
3. **Attach properties to a venue** — repeatable `property-value` editor (2D.4)
4. **Plugin landing / navigation shell** — replaces placeholder `HomePage.tsx`

## D4 — Coordinates via address → geocode → map picker (epic AC, not raw lat/lng)

2D.2 AC is explicit: the current `VenueFormModal`'s raw lat/lng `<TextInput>`s
(already removed in 2D.1; a TODO marker remains at `VenueFormModal/index.tsx:363`)
are replaced by an **address field + geocode + map picker** that writes into the
`geo` (`shared.geo-point`) component's `latitude`/`longitude`. This is the one
genuinely novel interaction in the package and gets a dedicated Interaction Primitive

- Key Flow.

## D5 — EAV property-value editor is type-adaptive (2D.4 AC)

`property-value` carries a `definition` ref + a typed value. The value input **adapts
to the definition's `type`**: `boolean`→`Toggle`/`Checkbox`, `integer`→`NumberInput`,
`string`→`TextInput`, `enum`→`SingleSelect` populated from `definition.enumOptions`.
Values are **grouped by category and ordered by `sortOrder`** using `Accordion`.

## D6 — Modal vs Dialog split (DS v2 semantics)

- **`Modal`** (`Modal.Root/Content/Header/Body/Footer`) → the venue form (content entry).
- **`Dialog`** (`Dialog.Root/Content/...`) → destructive confirms (delete, bulk delete,
  bulk status). Reuse the existing `events-manager/ConfirmDialog` shape.

## D7 — RBAC drives visible state (2D.2/2D.4 AC)

- **Admin / Editor**: see and edit all venues; full property authoring.
- **Venue Manager**: scoped to their own venue only (list pre-filtered server-side;
  create disabled; property authoring section hidden — they consume definitions, not author).
  Empty/permission states are first-class, not afterthoughts.

## D8 — Brownfield reuse over net-new (relocate, don't rebuild)

2D.2 says the venue form is the events-manager `VenueFormModal` **relocated** into the
venues plugin — no duplicate remains. The package therefore ships an **annotated
reference map** pointing the implementing LLM at the exact files to clone/adapt:
`VenueFormModal`, `Venues/index.tsx`, `StatusBadge`, `ConfirmDialog`, `PluginLayout`,
`SideNav`, `MediaInput`, `CitySelector`, `useVenuesEnhanced`.

## D9 — i18n: form chrome vs content fields

- Property `name`/`description` are **localized content** (`i18n.localized: true`) →
  per-locale editing (AR/FR/EN) in the authoring UI, with a locale switch.
- Venue admin **chrome** (labels, buttons) goes through Strapi `intlLabel` /
  `registerTrads` (existing `translations/{ar,fr,en}.json`). Per project-context:
  **Arabic uses Western numerals**, dates `DD/MM/YYYY`.
