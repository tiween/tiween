# Phase 05.1: Festival programme page (INSERTED) - Context

**Gathered:** 2026-11-08
**Status:** Ready for planning

<domain>
## Phase Boundary

A public, trilingual (FR/AR RTL/EN), mobile-first festival page at `/[locale]/festivals/[slug]`. It answers "what's on today and next", "what's on at this venue" and "where and when does this film play" for a film festival in under a minute. The launch festival is the JCC (Journées Cinématographiques de Carthage). Three views (By date default, By venue, By film) share a day strip. The page is driven by published Strapi data.

This discussion widened the phase to also cover:

- a full film detail page at `/[locale]/films/[slug]`;
- a TMDB-only film sourcing path for every festival film;
- an Event-groups admin page in events-manager with festival sections, programme editing and a JSON programme import;
- the two folded todos (original-language flag, TMDB images copied into ImageKit).

The confirmed design brief (`05.1-DESIGN-BRIEF.md`) is the authority for views, programme card, states, ranges, interaction, layout and the no-ticketing rule. Nothing here re-opens it. Out of scope: festivals index, theatre and music festivals, ratings and reviews, ticketing, carousels, mock data.

</domain>

<decisions>
## Implementation Decisions

### Carried forward from the confirmed design brief (not re-asked)

- **D-00:** `05.1-DESIGN-BRIEF.md` §1–7 is locked: the three views and the shared day strip; programme card with a visible ordered film list and total runtime; shorts-only header wording; feature listed last; states (Déjà projetés, empty day, cancelled/postponed with icon and text); URL-kept view/day/filters; 44px targets; full RTL; Gold Leaf × Aubergine; reused components; `lib/dates.ts` formats (`15h00` FR, `15:00` AR/EN, Western digits); WCAG 2.1 AA with axe-core clean in all three locales; no purchase action anywhere.
- **D-00b:** Build gate: phase `DESIGN.md` + `EXPERIENCE.md` + owner-approved Claude Design mockups (`mockup_status: approved`) before any build plan executes. The mockups must now also cover `/films/[slug]` and the Event-groups admin page (admin in the Strapi Design System).

### Films and the film detail page

- **D-01:** Tapping a film on the festival page opens a new **full film detail page `/[locale]/films/[slug]`**: poster, title, director, runtime, synopsis, credits, trailers, "Au festival" screenings, regular cinema showtimes where they exist, and related films. Shorts keep `/shorts/[slug]` (Phase 2) and get the same "Au festival" block. Ticketing stays dormant: showtimes on this page carry no purchase action either. — **Reversibility:** costly — new public route, sitemap and SEO surface; inbound links bind to it
- **D-02:** **Strict TMDB-only sourcing for every festival film, shorts included.** A work can only be placed in a festival programme if it carries a TMDB id (`externalIds`) and was imported through `tmdb-integration`. Owner intent: TMDB is the single source of truth, and Tiween enriches TMDB rather than keeping parallel data. Verified 2026-11-08: the TMDB API has **no create/edit movie endpoint** (writes are account/watchlist/favorite/rating/list only). A film missing from TMDB must therefore be **added by a person on themoviedb.org**, then imported by id. The admin should support this with a "not on TMDB? add it on themoviedb.org, then paste the id" path. The programme import rejects any film reference without a resolvable TMDB id. — **Reversibility:** costly — catalog shorts entered by hand (Phase 1) have no TMDB id and must be linked to TMDB before they can appear in a festival programme
- **D-03:** Existing hand-entered catalog shorts that appear in a festival must be linked to their TMDB entry (added on TMDB first if needed). The researcher should check TMDB's contribution rules and moderation for short films and new entries, and how fast a new entry becomes fetchable by id.
- **D-04:** Minimum record for a festival film to be published and shown: **title + director + runtime**. Poster optional (reserved stripe artwork fallback). The strict short-film publish rules from Phase 1 (poster, trailer or streaming link) do **not** apply to festival-only features. Catalog shorts keep their Phase 1 rules.
- **D-05:** Festival films are `creative-work` records (type `film` or `short-film`) in the `creative-works` plugin. No new film type.

### Folded todo: TMDB images into ImageKit

- **D-06:** On TMDB import, posters, backdrops and profiles are downloaded once and uploaded through the Strapi upload service into a Media Library folder mapped to ImageKit `tiween/tmdb/`. Reuse the SSRF-safe downloader and idempotent upload in `apps/strapi/scripts/seeds/utils/media-upload.ts`. Keep the TMDB proxy origin as a fallback for paths not copied yet. Check TMDB's terms on storing images and attribution before shipping (attribution likely needed on `/films/[slug]`).

### Folded todo: original-language flag

- **D-07:** Drop `originalTitle`. Every work gets an original-language flag that is one of the site locales (fr/ar/en), set by a per-locale "Original" toggle in WorkForm; the flagged locale's tab shows an "Original" badge. Migrate existing `originalTitle` values into the matching locale's `title`. The spoken-language field `language` stays separate. TMDB import maps `original_language` / `original_title` into this model. AI-draft translations take the original locale as their source (revisits Phase 1 D-13). — **Reversibility:** one-way — removes a stored attribute and migrates data; Phase 1 short-films API response shape (`originalTitle`) changes

### Festival sections and the film-team marker

- **D-08:** A section attaches **per programme**: an `event` points to one `festival-section` (new events-manager type belonging to an event-group, localized name, kind `competition | non-competition`, display order). If a festival mixes sections in one physical screening, the operator splits it or uses the programme's main section. — **Reversibility:** costly — schema relation that the import format and all three views depend on
- **D-09:** "Équipe du film présente" stays **per film slot** (screening `features`, category `event`). It shows as ✲ plus text on that film's row in the programme card. The card header adds a compact "✲ Équipe présente" summary when any film has it, so it's visible while scanning.
- **D-10:** Each festival screening listed on `/films/[slug]` and in the By-film view shows its section (trophy-outline glyph plus text for competition), so a film's competition status is visible outside the festival page too.

### Festival day and "now" logic

- **D-11:** A festival day runs **05:00–04:59 Africa/Tunis**. A 00:30 programme belongs to the previous evening's day, and its tile shows the real time with a next-day hint ("nuit" / translated).
- **D-12:** A programme moves under "Déjà projetés" **when it ends**: `endDateTime`, otherwise start plus total film runtime. A programme in progress stays in the main list with an "En cours" text label (not color alone). "Next screening" means the first programme not yet started.
- **D-13:** All festival times are shown and computed in **Africa/Tunis**, whatever the visitor's device zone. The server renders the local day; the client recomputes "now" on load and periodically so an open page stays correct. Time-zone handling goes through `lib/dates.ts`.

### Programme data entry and admin

- **D-14:** The programme is entered by **importing a JSON file in the admin**. Its structure is designed in this phase and built from the official programme. It describes the event-group, its sections, and programmes (date/time, venue, section, ordered films by TMDB id, per-film team-present flag, status). The import validates every row (unknown venue, missing/unresolvable TMDB id, unknown section, overlapping data), shows a dry-run report, then creates the records. — **Reversibility:** costly — the file format becomes the contract for every future festival
- **D-15:** **Claude drafts the JSON** from the official JCC programme (PDF/site) and resolves TMDB ids. The owner reviews the dry-run report (unresolved films and venues listed) before anything is published.
- **D-16:** **After import, the admin is the source of truth.** Last-minute changes (cancellation, postponement, time shift, team present, film order) are edited in the admin, not by re-importing. Any re-import must never silently overwrite admin edits: either create-only for new keys, or an explicit per-row conflict review (planner decides).
- **D-17:** A new **Event-groups page in the events-manager admin** (Strapi Design System v2), generic across event-group types, with festival-specific tabs: Info, Sections, Programme (per-day list; edit status, time, film order, team present), Import. Reuse `SubEventModal` and Planning patterns where they fit. Plugin-first: everything in `apps/strapi/src/plugins/events-manager/`.
- **D-18:** Only **admins/editors** manage festivals. Venue managers get no festival access in v1.
- **D-19:** Freshness: published admin changes appear on the public festival page and the affected `/films/[slug]` pages **within about 1 minute** (on-demand revalidation triggered on publish/update, with a short time-based fallback).
- **D-20:** A **public read API** for a festival by slug is needed (none exists today: the client never reads event-groups). It returns published data only, in flat v5 shape, with no ticketing fields (`price`, `ticketTiers`, `ticketsAvailable`, `ticketsSold` excluded), a field allowlist and coded errors, following the Phase 1 short-films API conventions.

### Timing

- **D-21:** **Hard deadline: live before this year's JCC.** Exact 2026 dates are to be confirmed against the official programme. The planner should sequence for the deadline: festival data model, import and admin first, then the festival page, then `/films/[slug]`, so the festival page can ship even if the film page slips. The planner should flag schedule risk early.

### Claude's Discretion

- Storage for the original-language flag (D-07): non-localized `originalLocale` enum written by the per-locale toggle (leaning) vs a localized `isOriginal` boolean with a one-true constraint.
- Fetch strategy for the festival page: whole festival in one payload vs per day (the By-film view needs all days).
- JSON import file exact schema, stable keys and validation library (Zod, via `apps/strapi/src/shared/validation.ts`).
- Revalidation mechanism (webhook vs lifecycle → Next.js `revalidateTag`).
- How `/films/[slug]` related films are chosen.

### Folded Todos

- **Flag original language and drop the original title field** (`.planning/todos/pending/2026-10-23-flag-original-language-and-drop-the-original-title-field.md`). `originalTitle` duplicates data and hard-codes French as the original. It fits here because festival films come from TMDB with an original language and title that need a home. See D-07.
- **Copy TMDB images into the ImageKit tiween/tmdb folder** (`.planning/todos/pending/2026-10-24-copy-tmdb-images-into-imagekit-tiween-tmdb-folder.md`). TMDB images are hotlinked today. It fits because every festival film is a TMDB import (D-02). See D-06.

## Existing Code Insights

### Reusable Assets

- `events-manager` content types `event-group` (localized, `type: festival`, `events` 1:N, poster/hero), `event` (venue, `startDateTime`/`endDateTime`, `eventStatus` scheduled|cancelled|postponed|rescheduled, `eventGroup`), `screening` (`order`, own `startDateTime`, `videoFormat`, audio/subtitle language, `movie` → creative-work, `features` M:N), `feature` (localized label, category technical|event|accessibility). In other words: programme = event, film slot = screening.
- `tmdb-integration` plugin: `/search` and `/movie/:id` routes; `services/movie.ts`, `image.ts`, `tmdb-client.ts`. This is the base for TMDB-only import and the image copy.
- `creative-work.externalIds` already exists to hold the TMDB id; `originalTitle` is still present (removed by D-07).
- `apps/strapi/scripts/seeds/utils/media-upload.ts`: SSRF-safe, idempotent media upload, reused for TMDB images.
- Admin: `PlanningTab` / `PlanningCalendarNew` (event-group filter via `useEventGroups`), `SubEventModal` (screening editing), `pages/Import` (external-source import list), WorkForm.
- Client: `features/events/components/{DateSelector,EventVenueFilter,EventCard,Map,ShareDialog}`, `features/venues/components/VenueCard`, `features/films/components/FilmCard`, `components/common/EmptyState`, `lib/dates.ts`, `lib/strapi-api/content/*` (server fetch layer).

### Established Patterns

- Public reads are dedicated content-API routes with forced `status: 'published'`, a field allowlist, flat v5 shape and Zod-allowlisted params (Phase 1 short-films).
- Ticketing fields exist on `screening` (`price`, `ticketTiers`, `ticketsAvailable`, `ticketsSold`): they must never be exposed. The ticketing code stays dormant and is never deleted.
- Admin UI uses Strapi DS v2 only; forms use RHF + Zod; TanStack Query v5.

### Integration Points

- New `festival-section` content type in events-manager, plus the `event.section` relation.
- New public `GET` festival-by-slug route in events-manager; a new client fetcher in `lib/strapi-api/content/`.
- New client routes `app/[locale]/festivals/[slug]` and `app/[locale]/films/[slug]`; "Au festival" block also added to `/shorts/[slug]`.
- Revalidation hook from Strapi publish/update to the Next.js cache.
- Sitemap entries for festival and film pages (indexing rules from Phase 6).

<specifics>
## Specific Ideas

- Owner: "if a movie is missing from TMDB we should be able to add it to TMDB and use its data; this way we enrich the TMDB DB and we always have one source of truth."
- Owner: "craft a JSON file structure that we can build from the official program, and import it on the admin."
- Owner: "a festival is an event group." Reuse `event-group` with `type: festival`; no new festival type.
- JCC ranges from the brief (1–10 days, 1–15 venues, 0–80 programmes/day, 1–8 films/programme) must be checked against the real programme before the mockups.

</specifics>
