**Films and the film detail page**

- **D-01:** Tapping a film on the festival page opens a new **full film detail page `/[locale]/films/[slug]`**: poster, title, director, runtime, synopsis, credits, trailers, "Au festival" screenings, regular cinema showtimes where they exist, and related films. Shorts keep `/shorts/[slug]` (Phase 2) and get the same "Au festival" block. Ticketing stays dormant: showtimes on this page carry no purchase action either. — Reversibility: costly — new public route, sitemap and SEO surface; inbound links bind to it
- **D-02:** **Strict TMDB-only sourcing for every festival film, shorts included.** A work can only be placed in a festival programme if it carries a TMDB id (`externalIds`) and was imported through `tmdb-integration`. Owner intent: TMDB is the single source of truth, and Tiween enriches TMDB rather than keeping parallel data. Verified 2026-11-08: the TMDB API has **no create/edit movie endpoint** (writes are account/watchlist/favorite/rating/list only). A film missing from TMDB must therefore be **added by a person on themoviedb.org**, then imported by id. The admin should support this with a "not on TMDB? add it on themoviedb.org, then paste the id" path. The programme import rejects any film reference without a resolvable TMDB id. — Reversibility: costly — catalog shorts entered by hand (Phase 1) have no TMDB id and must be linked to TMDB before they can appear in a festival programme
- **D-03:** Existing hand-entered catalog shorts that appear in a festival must be linked to their TMDB entry (added on TMDB first if needed). The researcher should check TMDB's contribution rules and moderation for short films and new entries, and how fast a new entry becomes fetchable by id.
- **D-04:** Minimum record for a festival film to be published and shown: **title + director + runtime**. Poster optional (reserved stripe artwork fallback). The strict short-film publish rules from Phase 1 (poster, trailer or streaming link) do **not** apply to festival-only features. Catalog shorts keep their Phase 1 rules.
- **D-05:** Festival films are `creative-work` records (type `film` or `short-film`) in the `creative-works` plugin. No new film type.

**Folded todo: TMDB images into ImageKit**

- **D-06:** On TMDB import, posters, backdrops and profiles are downloaded once and uploaded through the Strapi upload service into a Media Library folder mapped to ImageKit `tiween/tmdb/`. Reuse the SSRF-safe downloader and idempotent upload in `apps/strapi/scripts/seeds/utils/media-upload.ts`. Keep the TMDB proxy origin as a fallback for paths not copied yet. Check TMDB's terms on storing images and attribution before shipping (attribution likely needed on `/films/[slug]`).

**Folded todo: original-language flag**

- **D-07:** Drop `originalTitle`. Every work gets an original-language flag that is one of the site locales (fr/ar/en), set by a per-locale "Original" toggle in WorkForm; the flagged locale's tab shows an "Original" badge. Migrate existing `originalTitle` values into the matching locale's `title`. The spoken-language field `language` stays separate. TMDB import maps `original_language` / `original_title` into this model. AI-draft translations take the original locale as their source (revisits Phase 1 D-13). — Reversibility: one-way — removes a stored attribute and migrates data; Phase 1 short-films API response shape (`originalTitle`) changes

**Festival sections and the film-team marker**

- **D-08:** A section attaches **per programme**: an `event` points to one `festival-section` (new events-manager type belonging to an event-group, localized name, kind `competition | non-competition`, display order). If a festival mixes sections in one physical screening, the operator splits it or uses the programme's main section. — Reversibility: costly — schema relation that the import format and all three views depend on
- **D-09:** "Équipe du film présente" stays **per film slot** (screening `features`, category `event`). It shows as ✲ plus text on that film's row in the programme card. The card header adds a compact "✲ Équipe présente" summary when any film has it, so it's visible while scanning.
- **D-10:** Each festival screening listed on `/films/[slug]` and in the By-film view shows its section (trophy-outline glyph plus text for competition), so a film's competition status is visible outside the festival page too.

**Festival day and "now" logic**

- **D-11:** A festival day runs **05:00–04:59 Africa/Tunis**. A 00:30 programme belongs to the previous evening's day, and its tile shows the real time with a next-day hint ("nuit" / translated).
- **D-12:** A programme moves under "Déjà projetés" **when it ends**: `endDateTime`, otherwise start plus total film runtime. A programme in progress stays in the main list with an "En cours" text label (not color alone). "Next screening" means the first programme not yet started.
- **D-13:** All festival times are shown and computed in **Africa/Tunis**, whatever the visitor's device zone. The server renders the local day; the client recomputes "now" on load and periodically so an open page stays correct. Time-zone handling goes through `lib/dates.ts`.

**Programme data entry and admin**

- **D-14:** The programme is entered by **importing a JSON file in the admin**. Its structure is designed in this phase and built from the official programme. It describes the event-group, its sections, and programmes (date/time, venue, section, ordered films by TMDB id, per-film team-present flag, status). The import validates every row (unknown venue, missing/unresolvable TMDB id, unknown section, overlapping data), shows a dry-run report, then creates the records. — Reversibility: costly — the file format becomes the contract for every future festival
- **D-15:** **Claude drafts the JSON** from the official JCC programme (PDF/site) and resolves TMDB ids. The owner reviews the dry-run report (unresolved films and venues listed) before anything is published.
- **D-16:** **After import, the admin is the source of truth.** Last-minute changes (cancellation, postponement, time shift, team present, film order) are edited in the admin, not by re-importing. Any re-import must never silently overwrite admin edits: either create-only for new keys, or an explicit per-row conflict review (planner decides).
- **D-17:** A new **Event-groups page in the events-manager admin** (Strapi Design System v2), generic across event-group types, with festival-specific tabs: Info, Sections, Programme (per-day list; edit status, time, film order, team present), Import. Reuse `SubEventModal` and Planning patterns where they fit. Plugin-first: everything in `apps/strapi/src/plugins/events-manager/`.
- **D-18:** Only **admins/editors** manage festivals. Venue managers get no festival access in v1.
- **D-19:** Freshness: published admin changes appear on the public festival page and the affected `/films/[slug]` pages **within about 1 minute** (on-demand revalidation triggered on publish/update, with a short time-based fallback).
- **D-20:** A **public read API** for a festival by slug is needed (none exists today: the client never reads event-groups). It returns published data only, in flat v5 shape, with no ticketing fields (`price`, `ticketTiers`, `ticketsAvailable`, `ticketsSold` excluded), a field allowlist and coded errors, following the Phase 1 short-films API conventions.

**Timing**

- **D-21:** **Hard deadline: live before this year's JCC.** Exact 2026 dates are to be confirmed against the official programme. The planner should sequence for the deadline: festival data model, import and admin first, then the festival page, then `/films/[slug]`, so the festival page can ship even if the film page slips. ## Summary

The festival feature is mostly **new plumbing around existing models**: `event-group` (type `festival`), `event` (programme), `screening` (film slot), `feature`, `creative-work`, `venue` all exist and are exposed to nobody publicly (the client never reads event-groups). The heavy lifting is (1) a server-side **TMDB-to-creative-work importer that does not exist today** (today `tmdb-integration` only proxies `/search` and `/movie/:id` to the admin browser; nothing creates a creative-work, person, credit or image from TMDB), (2) the `originalTitle` to `originalLocale` one-way migration, (3) a new public read API and a normalized whole-festival payload, (4) the admin Event-groups page and a two-step JSON import, and (5) the client festival page with Africa/Tunis day logic. A second unplanned item is the **`/films/[slug]` composite**, which must be assembled across two plugins without creating a plugin cycle.

**Four findings change the plan and need an owner decision before planning.** (a) Festival-only shorts, which are about 40% of a JCC lineup (69 of 165 films in 2025), would be blocked from publishing by the Phase 1 `short-film` publish guard (poster and watch source required) and, once published, would flood the public shorts directory; D-04 cannot be met without a rule change. (b) TMDB's API terms forbid commercial use without a written agreement, cap caching at 6 months and prohibit "derivatives", which collides with D-06's permanent image copy and the "TMDB is our source of truth" model; non-commercial use with attribution is allowed, and v1 has no revenue model, but the owner should confirm. (c) D-07 says the original language is always fr/ar/en, but JCC films are often originally Wolof, Amharic, Swahili, Persian, Portuguese and so on, so `original_title` has no home for those. (d) The **official 2026 programme is not published**: JCC 37 runs **12–19 December 2026** (8 days, 34 days from today), and the last two editions revealed the detailed programme between 9 days before opening and opening day, so data entry will be last-minute and the importer must be finished and rehearsed well before it lands.

**Primary recommendation:** Build in this order: spikes and decisions, then `originalLocale` migration + `festival-section` + public API + normalized payload, then the TMDB film importer and programme import (two steps, resumable), then the admin page, then the festival page, then `/films/[slug]`; give the client a whole-festival tagged fetch (`festivals` tag, `{ expire: 0 }` on-demand revalidation from a Strapi document middleware, 60 s TTL fallback) and keep the festival route static-eligible by reading view/day/filters from the URL in a client island only. Split the design-gated UI work from the backend work so the backend can plan under a documented waiver while mockups are produced.

### Pattern 1: festival-section + event.section (FEST-02)

**What:** New collection type in events-manager: `festival-section` (`draftAndPublish: true`, i18n localized on `name`; non-localized `slug` uid used as the stable import key per festival, `kind` enum `competition | non-competition`, `order` integer, `eventGroup` manyToOne). `event.section` manyToOne to it (non-localized relation). All additive; no existing attribute changes.
**When to use:** D-08. **Keep section keys unique per festival** (`<festival>-<key>` in the uid) since `uid` is globally unique.
**Gotcha:** a published event only shows the section when the section is **published** (published documents drop relations to draft targets, Phase 1 finding A4). Import must publish sections before events.

### Pattern 2: Public read API shape (FEST-03)

**What:** `GET /api/events-manager/festivals/:slug?locale=` (`auth: false`, rate limit via `createRateLimit`). Strict Zod query (`locale` only), slug param regex as in `shortFilmSlugParamSchema`. Coded errors: `VALIDATION_FAILED` 400, `UNSUPPORTED_LOCALE` 400, `FESTIVAL_NOT_FOUND` 404; unmapped becomes a logged 500 `INTERNAL_ERROR` (copy `respondError`/`STATUS_BY_CODE`). Resolve the festival on its **default-locale (fr) row** (the uid slug is not copied to non-default rows, Phase 1 A3) and overlay requested-locale titles for the documents served (relations from non-default rows are dropped, A4).
**Response:** one normalized document:

```
{ data: {
    festival: { documentId, slug, locale, title, shortTitle, subtitle, startDate, endDate,
                timezone: "Africa/Tunis", poster, hero },
    sections: [{ documentId, key, name, kind, order }],
    venues:   [{ documentId, slug, name, address, geo, city }],
    films:    [{ documentId, slug, type, title, originalLocale, directors:[{name}], duration, poster, route }],
    programmes: [{ documentId, key, start, end, status, venue: <documentId>, section: <documentId|null>,
                   title, slots: [{ order, film: <documentId>, teamPresent }] }]
  }, meta: { generatedAt } }
```

No `price`, `ticketTiers`, `ticketsAvailable`, `ticketsSold`, no numeric `id`, no audit fields. `route` is `"films"` or `"shorts"` so the client builds the link without type logic (see Open Question 3). `teamPresent` is derived from the feature slug `team-present` so the client never touches the vocabulary.
**Query:** one `strapi.documents(EVENT_UID).findMany({ filters: { eventGroup: { documentId } }, status: "published", locale: default, populate: {...}, limit })` with explicit paging (Document Service default limit is small; never rely on the default; the REST `maxLimit: 100` in `config/api.ts` governs REST only). Expect hundreds of events and about 1000 screenings: page in 100s.

**Payload size estimate (the normalization removes duplication):**

| Part       | Count (JCC worst case) | ~Bytes each                                   | Raw                                                                              |
| ---------- | ---------------------- | --------------------------------------------- | -------------------------------------------------------------------------------- |
| films      | 220                    | 500 (title, 1–2 directors, poster url, flags) | 110 KB                                                                           |
| venues     | 25                     | 300                                           | 8 KB                                                                             |
| sections   | 10                     | 200                                           | 2 KB                                                                             |
| programmes | 400                    | 250                                           | 100 KB                                                                           |
| slots      | 800                    | 80                                            | 64 KB                                                                            |
| **Total**  |                        |                                               | **about 285 KB raw, about 50 KB gzip** `[ASSUMED: arithmetic on assumed counts]` |

Embedding the film in every slot would be about 500 KB raw. Both are far below the Next data cache per-item ceiling (about 2 MB, `[ASSUMED]` from training knowledge — not confirmed in the docs fetched). **Recommendation: whole festival in one payload.** The By-film view needs all days anyway, the day strip then switches instantly with no network, and a single tagged cache entry makes revalidation one call. Pass the island a slim, already-normalized object (it is serialized into the RSC payload once).

### Pattern 3: Client page and data flow (FEST-05..08)

- `app/[locale]/festivals/[slug]/page.tsx`: Server Component, `setRequestLocale(locale)`, `await params` (Next 16), fetch the festival via `PublicStrapiClient.fetchAPI(path, { locale }, { next: { tags: ["festivals", `festival:${slug}`], revalidate: 60 } })` (the base client forwards `next` and keeps the `tags`: `[VERIFIED: apps/client/src/lib/strapi-api/base.ts:55-60]`). 404 via `notFound()` on `FESTIVAL_NOT_FOUND`; any other failure renders an error state with retry, never an empty festival.
- **Do not read `searchParams` on the server.** It would make the route dynamic per request. A client island reads view/day/filters with `useSearchParams` (inside `<Suspense>`) and writes them with `router.replace` (shareable link, back-button safe). The server HTML renders a sensible default (festival day at render time in Africa/Tunis); the island recomputes on mount in an effect and every 30–60 s (D-13), never during render, to avoid a hydration mismatch.
- Programme card, day strip, view switch and chips are new components in `features/festivals/`. Day strip: `overflow-x-auto` with CSS `scroll-snap-type`, logical properties (`ms-`/`ps-`), `scrollIntoView({ inline: "center" })` for the active day, buttons at least 44 px.
- Map link: use an external maps URL from `geo` (`https://www.google.com/maps/search/?api=1&query=lat,lng`), not 25 Leaflet maps.
- Numbers and dates: `toNumeralSafeLocale(locale)` for `Intl`; FR time as `HH[h]mm`, AR/EN as `Intl` with `hourCycle: "h23"` (verified below).

### Pattern 4: Festival-day and "now" logic (FEST-04)

Pure functions in `lib/festival-time.ts`, all taking `now` as a parameter. Africa/Tunis was UTC+01:00 on both a December and a July sample date in Node's ICU `[VERIFIED: node Intl run this session: 2026-12-12 → "GMT+01:00", 2026-07-01 → "GMT+01:00"]`, so fixed-offset thinking is safe but still compute through `dayjs.tz`. See Code Examples.

### Pattern 5: JSON import (FEST-10)

Two admin routes (`type: "admin"`, policy `festivals-manage`): `POST /events-manager/festival-import/dry-run` and `/commit`. Both parse the **same** body with the strict Zod schema; commit re-validates and re-resolves everything (it never trusts a client-held report). Dry-run is read-only. The body must stay under Strapi's JSON body limit (default `strapi::body` in `config/middlewares.ts:82` has no custom config; the koa-body default is 1 MB `[ASSUMED]`); a JCC file is estimated at 100–300 KB. Add a realistic-size test.

**Coded issue vocabulary (errors block commit; warnings do not):** `SCHEMA_INVALID`, `DUPLICATE_PROGRAMME_KEY`, `UNKNOWN_VENUE`, `UNKNOWN_SECTION`, `FILM_NOT_IMPORTED` (tmdbId valid but no catalog work: run Step 1), `TMDB_ID_UNRESOLVED`, `FILM_BELOW_MINIMUM` (no director or runtime, D-04), `OUTSIDE_FESTIVAL_RANGE`, `STATUS_INVALID`, warnings `VENUE_OVERLAP`, `EXISTING_PROGRAMME_SKIPPED`, `EXISTING_DIFFERS` (informational diff, never applied).

**Re-import policy recommendation (D-16): create-only.** New keys are created; keys that already exist are **skipped and reported** (with a read-only diff of what the file says versus the stored value). No overwrite path, no per-row conflict UI. Rationale: deadline, and D-16 makes the admin authoritative. An operator who wants a different value edits it in the admin.

**Two-step pipeline (important):** TMDB resolution is slow. `tmdb-client` allows 40 requests per 10 s (token bucket, `acquireToken`), so about 220 `getDetails` calls take roughly 45 s of pure waiting, plus 2 image downloads/uploads per film (sharp thumbnails make each upload take on the order of a second). One HTTP request cannot carry that. So **Step 1 "Prepare films"** takes the distinct `tmdbId`s from the file and imports them in resumable batches of about 20 per request (idempotent by `externalIds.tmdbId`), with a progress list; **Step 2 "Import programme"** is DB-only and fast. Step 2 reports `FILM_NOT_IMPORTED` for anything Step 1 has not done.

### Pattern 7: Server-side TMDB import (FEST-11)

**There is no such importer today** (verified: no code calls `strapi.documents(CREATIVE_WORK_UID).create` from TMDB data; `tmdbId` appears only in WorkForm, the `external-ids` component and the admin hook). Build `creative-works/services/tmdb-import.ts` exposed through the creative-works facade (`importWorkFromTmdb(tmdbId)`, `findWorkByTmdbId(tmdbId)`), calling `strapi.plugin("tmdb-integration").service("movie")` (R5 allows it). Mapping:

- type: `short-film` if TMDB `runtime` is at most 40 (the project's own threshold constant `SHORT_FILM_DURATION_WARNING_MINUTES` is already used by the rules module) and there is no feature indication, else `film`; the operator can override in the dry-run step.
- localized `title`/`synopsis` for fr/ar/en from `getDetails` per locale (or the `translations` append); fall back to the default-locale value per locale (`createWork` replicates verbatim to all locales and publishes, a reusable pattern).
- `originalLocale` from `original_language` only when it is one of fr/ar/en (see Open Question 4).
- `credits[]`: directors (job `Director`) with `creditRole` slug `director` (exists in `scripts/seeds/data/credit-roles.json`); persons found-or-created by name+tmdb person id (`person.externalIds` component exists); `cast[]` top 5–10.
- `genres`: TMDB genre id to the 15 local genre slugs (`scripts/seeds/data/genres.json`); unmapped genres are dropped, not created.
- `externalIds`: `{ tmdbId, imdbId, lastSyncedAt }`.
- `duration` from `runtime`; slug deterministic `<slugified title>-<year>` with `-<tmdbId>` appended on collision (do not rely on uid auto-generation through the Document Service).
- Idempotent: find by `externalIds.tmdbId` first; existing works get **gap-fill only** (fill empty fields, never overwrite curated values), so a hand-entered Phase 1 short linked by setting its `tmdbId` in WorkForm is enriched, not clobbered.

### Pattern 8: TMDB images to ImageKit `tiween/tmdb/` (FEST-12)

2. Allow host `image.tmdb.org` for the TMDB call site only (the downloader takes `allowedHosts` per call).
3. Image names: `tmdb-<tmdbId>-poster` etc. (must match `STEM_PATTERN`); folder chain `["tmdb"]` at Media Library root.

### Pattern 9: `/films/[slug]` without a plugin cycle (FEST-14)

`events-manager` already depends on `creative-works` (a screening points to a work; `sub-event-work-kind.ts` calls `strapi.plugin("creative-works")`; `venue-events.ts` uses its facade). The reverse call would create a cycle, forbidden by R1/R2 (`docs/context/plugin-dependency-rules.md`). So:

- `creative-works`: `GET /creative-works/films/:slug` (+ `/related`), built on the same projection helpers as `short-films.ts` but filtering `type: { $in: ["film","short-film"] }` for the detail.
- `events-manager`: `GET /events-manager/works/:documentId/screenings` returning festival and regular showtimes for one work, projected like the festival payload (no purchase fields; reuse the `sanitizeScreening` key stripping plus an explicit allowlist).
- The page server component calls both in parallel (`Promise.all`) with separate tags (`film:<slug>`, `festivals`) and renders. This keeps the two plugins decoupled and lets the schedule part refresh independently.

**Related films (discretion):** deterministic, reuse the Phase 1 rule order: same director first, then shared genre, then same festival section or programme co-occurrence, fill to 6 by latest `publishedAt`. No ML, no Meilisearch dependency (Phase 3 may later replace it, with this logic as fallback, exactly as SRCH-03 states for shorts).

### Pattern 10: Revalidation (FEST-15)

- **Strapi side:** a Document Service middleware in events-manager (registered at plugin `register`, as Phase 1 did for the publish guard; `strapi.documents.use` cannot be unregistered, so tests use one shared resettable instance, Phase 1 STATE note) for actions `publish`, `unpublish`, `delete` (and `create` with `status: "published"`) on `event-group`, `festival-section`, `event`, `screening`, `feature`, `venue`, and creative-work changes. It calls `scheduleRevalidate(tags)`: a **trailing debounce of about 2 s** that coalesces bursts, then `POST ${CLIENT_URL}/api/revalidate` with a shared secret header, 3 s timeout, 2 retries, errors logged and swallowed (never block a save). Bulk import suppresses per-write calls and sends one at the end. Tags: `festivals` (every festival page; at launch there is one) and `film:<slug>`. This avoids mapping a screening back to its festival. `CLIENT_URL` already exists in the Strapi env template (`apps/strapi/.env.example:207`); add `REVALIDATE_SECRET` on both sides and declare it in `apps/client/src/env.mjs`.
- **Next side:** `app/api/revalidate/route.ts` (`POST`; the proxy matcher excludes `api`, verified in `proxy.ts` `config.matcher`), `timingSafeEqual` secret check, then `revalidateTag(tag, { expire: 0 })`. Use `{ expire: 0 }`, not `"max"`: `"max"` is stale-while-revalidate, so the first visitor after an edit would still see stale content, which can violate the one-minute goal. The docs describe `{ expire: 0 }` "for webhook scenarios" `[CITED: Context7 /vercel/next.js/v16.1.6 revalidateTag.mdx]`; the repo runs 16.1.1, so confirm with a test.
- **Fallback:** `next: { revalidate: 60 }` on the fetch means a missed webhook heals within a minute (D-19's "short time-based fallback"); the base client already defaults to 60.

### Anti-Patterns to Avoid

- **Reading `searchParams` in the festival Server Component:** makes the page dynamic per request and breaks sharing a single cached payload.
- **Computing "today" with `new Date()`/`isToday()`/`getToday()`:** these use the runtime zone; a UTC server shows the wrong festival day around midnight. Use the Tunis helpers.
- **Doing TMDB and image work inside the programme-import request:** it will exceed proxy timeouts; use the two-step pipeline.
- **Calling `strapi.documents()` with a foreign UID or `creative-works` calling `events-manager`:** violates R3/R4 or R1.
- **Exposing the existing event sanitizer output:** `sanitizeScreening` still returns `price`; build an explicit allowlist.
- **Dropping `original_title` column in the same deploy as the first code change that stops reading it** (see Pitfall 1).
- **Writing `events` in only one locale and publishing with the default locale only:** the event type is localized (`i18n.localized: true`); publish with `locale: "*"` like `createWork` does.

## Common Pitfalls

### Pitfall 1: One-way column drop on an auto-deploying `main`

**What goes wrong:** removing `originalTitle` from `schema.json` makes Strapi's schema diff drop the column at the next boot; `main` auto-deploys to production, and a failed or heuristic-wrong backfill is unrecoverable.
**Why it happens:** `@strapi/database` schema `diff` emits `removedColumns` and the builder calls `dropColumn` `[VERIFIED: node_modules/@strapi/database/dist/schema/diff.js:153-183; builder.js:214-218,285]`. User migrations run **before** `syncSchema()` `[VERIFIED: the header of apps/strapi/database/migrations/2026.08.04T00.00.00.watchlist-dedupe-key.js, citing @strapi/database/dist/schema/index.js:69-73]`, and at migration time the new column does not exist yet, so the migration must create `original_locale` itself (the precedent migration does exactly that for `dedupe_key`).
**How to avoid:** expand/contract in two commits. Commit A: add `originalLocale` (nullable), the migration backfills it and copies original titles, all readers switch (derived `originalTitle` in the API), `originalTitle` is still in the schema. Commit B (after production is verified and a DB backup is taken): remove `originalTitle`. Heuristic for the backfill, in order: (1) `originalTitle` equals an existing locale row's `title` → that locale; (2) `isArabicScript(originalTitle)` → `ar`; (3) otherwise `fr` (the Phase 1 source) and **log the document for manual review**. Never overwrite a non-empty target `title`.
**Warning signs:** rows with `original_locale` null after the migration; a short film whose Arabic title changed; documents in the migration's manual-review log.

### Pitfall 2: Publish cascade hides data silently

**What goes wrong:** the public festival payload is missing films, sections or venues even though the import "succeeded".
**Why it happens:** event, screening, section, feature, venue and creative-work are all draft/publish; published documents drop relations to draft targets (Phase 1 finding A4); `event` is localized so a default-locale-only publish leaves other locales draft.
**How to avoid:** import publishes in dependency order (venue and works pre-exist; then features, sections, events with `locale: "*"`, screenings); the dry-run lists any referenced venue or work that is not published; a boot test asserts the full payload after import in all three locales.

### Pitfall 3: Phase 1 publish guard blocks festival shorts

**What goes wrong:** a TMDB-imported `short-film` without poster and watch source cannot be published (`POSTER_REQUIRED`, `WATCH_SOURCE_REQUIRED`; `SKIPPABLE_ISSUE_CODES` allows only `POSTER_REQUIRED` and only through the importer-scope bypass `[VERIFIED: apps/strapi/src/shared/short-film-rules.ts:347 and 478-498]`), so about 40% of JCC films are missing from the page. See Open Question 1.

### Pitfall 4: Vitest `include` is a whitelist

**What goes wrong:** new client tests never run. `apps/client/vitest.config.ts` lists explicit globs (its own comments describe silent never-run tests), none of which match `features/festivals/**`, `app/**/festivals/**`, `app/**/films/**` or `lib/festival-*.test.ts`.
**How to avoid:** add the globs in the first plan that adds a test, and add an explicit "the new test file is actually collected" check (run it by path and confirm it reports).

### Pitfall 5: Server timezone is not Tunis

**What goes wrong:** "today", day boundaries and `En cours` are off by one hour or one day on a UTC server; `new Date().setHours(0,0,0,0)` patterns (`DateSelector`, `server.ts getDateRange`) already have a documented off-by-one (`toISODate` comment in `server.ts`).
**How to avoid:** every festival date goes through `dayjs.tz(..., "Africa/Tunis")`/`Intl timeZone`; tests run with `TZ=UTC` and `TZ=America/Los_Angeles` and must give identical results.

### Pitfall 6: `team-present` vocabulary does not exist

**What goes wrong:** the ✲ marker never shows because no `feature` record exists, or exists in one locale only (localized target; Phase 1 A4).
**How to avoid:** the importer/bootstrap find-or-create slug `team-present`, category `event`, labels fr/ar/en, all published; the API derives `teamPresent`; a test asserts it in `ar`.

### Pitfall 7: Next cache and the `searchParams` trap

Reading `searchParams` (or `cookies()`) on the server makes the festival route dynamic; the data cache still works but you lose full-route caching and the benefit for a traffic spike on a single replica. Keep state in the client island.

### Pitfall 8: Hydration mismatch from time

Rendering "En cours"/"now" labels during server render and again on the client with a different `Date.now()` throws hydration warnings. Compute "now" in an effect after mount; render the server default without time-dependent labels, or mark them with a stable server timestamp passed down.

### Pitfall 9: Arabic time format

`new Intl.DateTimeFormat("ar-TN", { hour: "2-digit", minute: "2-digit" })` gave `03:00 م` (12-hour, Arabic suffix) in Node 22 `[VERIFIED: node run this session]`. Force `hourCycle: "h23"` and `-u-nu-latn` (verified output `15:00`). FR must be `HH[h]mm` by hand (Intl gives `15:00`). Midnight 00:30 formats correctly with `h23`.

### Pitfall 10: TMDB runtime/crew gaps break D-04

A newly contributed TMDB entry requires only original title and overview (TMDB bible), so runtime and director may be empty. `FILM_BELOW_MINIMUM` in the dry-run must surface these so the owner fixes them **on TMDB** (or, if the owner accepts, in Tiween as a stopgap) before the deadline.

## Code Examples

### Festival day and phase (pure, injectable now)

```ts
// apps/client/src/lib/festival-time.ts  (illustrative; tests in festival-time.test.ts)
import dayjs from "dayjs"

import "@/lib/dates" // side effect: registers utc/timezone/localizedFormat plugins

export const FESTIVAL_TZ = "Africa/Tunis"
const DAY_CUTOFF_HOURS = 5 // D-11: a festival day is 05:00-04:59

/** YYYY-MM-DD of the festival day an instant belongs to. */
export function festivalDay(instant: string | Date): string {
  return dayjs(instant)
    .tz(FESTIVAL_TZ)
    .subtract(DAY_CUTOFF_HOURS, "hour")
    .format("YYYY-MM-DD")
}

export type ProgrammePhase = "upcoming" | "inProgress" | "ended"

/** D-12: ended at endDateTime, else start + total runtime. */
export function programmePhase(
  p: { start: string; end?: string | null; totalRuntimeMin: number },
  now: Date
): ProgrammePhase {
  const start = dayjs(p.start)
  const end = p.end ? dayjs(p.end) : start.add(p.totalRuntimeMin, "minute")
  const t = dayjs(now)
  if (t.isBefore(start)) return "upcoming"
  return t.isBefore(end) ? "inProgress" : "ended"
}

/** FR "15h00"; AR/EN "15:00" with Western digits. */
export function formatFestivalTime(
  instant: string | Date,
  locale: string
): string {
  const d = dayjs(instant).tz(FESTIVAL_TZ)
  return locale === "fr" ? d.format("HH[h]mm") : d.format("HH:mm")
}
```

export async function POST(request: Request) {
  const provided = Buffer.from(request.headers.get("x-revalidate-secret") ?? "")
  const expected = Buffer.from(env.REVALIDATE_SECRET ?? "")
  if (
    expected.length === 0 ||
    provided.length !== expected.length ||
    !timingSafeEqual(provided, expected)
  ) {
    return Response.json({ revalidated: false }, { status: 401 })
  }
  const { tags } = (await request.json()) as { tags?: unknown }
  const list = Array.isArray(tags)
    ? tags.filter((t): t is string => typeof t === "string").slice(0, 50)
    : []
  for (const tag of list) revalidateTag(tag, { expire: 0 })
  return Response.json({ revalidated: true, count: list.length })
}

## Open Questions

1. **BLOCKING (owner): festival-only shorts versus the Phase 1 publish guard and the public shorts directory.**

   - What we know: the guard fires for `type === "short-film"` only (`short-film-publish-guard.ts:120,234`) and requires slug, poster (skippable only via the D-20 importer scope), director, and trailer-or-streaming-link (`short-film-rules.ts:478-498`). The public shorts API lists every published `short-film` (`short-films.ts` `filters: { type: SHORT_FILM_TYPE }`). 69 of 165 films at JCC 2025 were shorts.
   - What's unclear: D-04 says Phase 1 rules do not apply to "festival-only features"; it does not say how festival-only **shorts** are typed.
   - Recommendation: add an additive non-localized boolean `festivalOnly` (default false) on `creative-work`. The guard skips `POSTER_REQUIRED` and `WATCH_SOURCE_REQUIRED` for `festivalOnly` works (a pure change in `src/shared/short-film-rules.ts`, unit-testable) and the shorts directory/featured/related/sitemap queries exclude `festivalOnly: true`. The curator unticks it to promote a short into the directory (the guard then applies). The TMDB importer sets it on works it creates. Alternative if the owner prefers: import festival shorts as `type: film` and detect "shorts-only programme" by the 40-minute threshold, at the cost of the semantic type and the shorts "Au festival" block.

2. **BLOCKING (owner): TMDB API terms versus D-06 and the TMDB-as-source model.**

   - What we know: [CITED: themoviedb.org/api-terms-of-use] no commercial use without a separate written agreement; no caching "for longer than 6 months any information obtained through or from TMDB"; no "derivatives"; purge on termination; required notice "uses TMDB and the TMDB APIs but is not endorsed, certified, or otherwise approved by TMDB" and the TMDB logo, visually subordinate. The API FAQ adds: non-commercial use is free with attribution; attribution goes in an About/Credits section and links to themoviedb.org. (Both fetched through a summarizing tool; the owner should read §1.C and §1.D of the terms.)
   - What's unclear: whether storing TMDB text and images permanently in Strapi and ImageKit, and presenting them on a public site, is acceptable; whether a free public cultural directory with dormant ticketing is "commercial".
   - Recommendation: proceed on the non-commercial path with attribution on `/films/[slug]` and an About/Credits surface, store `externalIds.lastSyncedAt` and plan a re-sync at least every 6 months, and have the owner email TMDB for written confirmation of the permanent-copy model now. Treat it as a launch-readiness item (FEST-12), not an engineering blocker.

3. **Where shorts link from the festival page (D-01) while Phase 2 is unbuilt.**

   - What we know: `app/[locale]/shorts/[slug]/page.tsx` still reads `mock-shorts` (verified); Phase 2 (SPAGE-01) has 0 plans; Phase 05.1 "depends on Phase 1, 2, 4".
   - Recommendation: the festival payload carries `route: "films" | "shorts"` per film, set by one function. Default shorts to `/shorts/[slug]` per D-01 **only after SPAGE-01 ships**; until then return `films` so no link 404s. If Phase 2 will not ship before 12 Dec, let `/films/[slug]` serve shorts too and revisit.

4. **D-07 and non-site original languages (data loss).**

   - What we know: TMDB `original_language` is any ISO 639-1 code; D-07 allows only fr/ar/en; the todo says "no fallback for non-site languages" but that was decided for catalog shorts, not JCC features.
   - Recommendation: for `fr/ar/en` originals set `originalLocale` and put TMDB `original_title` into that locale's `title`; for any other language set `originalLocale = null`, keep the fr `title` (TMDB French translation, else TMDB `title`) and accept that the foreign-language original title is not stored in v1. Confirm with the owner; the alternative is one nullable non-localized "foreign original title" string, which reintroduces `originalTitle` in a narrower form.

5. **Indexability of the new pages before the Phase 6 go-live.**

   - What we know: shorts pages set `robots: { index: false }` until go-live; `robots.ts` already allows crawling in production; there is no festival SEO requirement yet. JCC discovery traffic is largely search.
   - Recommendation: add SEO requirement FEST-14/16 detail: festival and film pages are indexable in production only (`isProduction()`), with metadata, canonical and hreflang, sitemap entries; the owner confirms they may be indexed before the shorts directory is.

6. **Is `TMDB_API_KEY` configured in the production Strapi?** It appears in no `.env.example` and no deploy file I could read (`grep TMDB` over `.github`, compose and `.env.example` found nothing). Add it to `.env.example`, and have the owner confirm the production secret exists.

7. **Final programme source.** No PDF/URL could be fetched (official site unreachable here). Owner to supply the programme link or file when published; until then use a synthetic fixture modeled on the 2025 numbers.

### Known Threat Patterns for this stack

| Pattern                                                               | STRIDE                             | Standard Mitigation                                                                                                                            |
| --------------------------------------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Leaking `price`/`ticketTiers`/inventory counts through the public API | Information disclosure             | Explicit allowlist projection, test asserting key set equality (not only absence)                                                              |
| Forged revalidation calls (cache purge DoS)                           | Denial of service / Tampering      | Shared secret, timing-safe compare, tag count cap, only known tag shapes accepted                                                              |
| SSRF through TMDB-derived image paths                                 | Tampering / Information disclosure | Build URLs from the fixed `https://image.tmdb.org/t/p/<size>` base plus a validated path (`/^\/[A-Za-z0-9._-]+$/`), then the vetted downloader |
| Malicious or oversized import JSON                                    | Denial of service                  | Body limit, `.strict()` schema, caps (programmes, films per programme, string lengths), dry-run does no writes                                 |
| Stored XSS via imported text (TMDB overview, titles)                  | Tampering                          | Store as text, render escaped; synopsis is `richtext` on the schema, so sanitize or render as plain text on the client                         |
| Privilege escalation to venue managers editing festivals              | Elevation of privilege             | Admin RBAC action not granted to the venue-manager role; policy fails closed                                                                   |
| Unpublished/draft festival data leaking                               | Information disclosure             | Force `status: "published"` and default-locale filters in the service, never from the query                                                    |
| Stale cached cancellation shown to visitors                           | (integrity of service)             | `{ expire: 0 }` revalidation + 60 s TTL; status shown as text                                                                                  |

## Design-step notes (for DESIGN.md / EXPERIENCE.md / mockups)

- **Real ranges:** 8 days (12–19 Dec 2026), design for up to about 25 venues and 20–50 (peak higher, ceiling 80) programmes per day, 1–8 films per programme, 165–220 distinct films.
- **Net-new components, not reuse:** the day strip, programme card, view switch, section chips. `DateSelector` (today/tomorrow popover) and `EventVenueFilter` (single-select combobox) are not those. Say so in the mockups.
- **Data shape constraints:** each programme has `start`, optional `end`, `status`, one `venue`, optional one `section`, ordered slots; each film has `type`, `title` (locale with French fallback), director names, `duration`, optional poster (so the **stripe fallback is a first-class state**), `teamPresent` per slot, `originalLocale`. No price, no ticket state, no "sold out".
- **Time:** Africa/Tunis only, day 05:00–04:59, "nuit" hint after midnight, FR `15h00`, AR/EN `15:00`, Western digits, `<bdi>` around Arabic/Latin titles.
- **Fields that can be absent:** section (programme without section), venue `geo`/`address` (regional sites), poster, director (never at publish, but dry-run exceptions), synopsis, trailer.
- **Admin mockup (Strapi DS v2):** tabs Info / Sections / Programme / Import; Import has two steps (Prepare films with batch progress and unresolved TMDB ids; Import programme with dry-run report listing coded issues); Programme tab edits status/time/film order/team present and saves-and-publishes in one action.
- **Film page:** TMDB attribution notice and logo, "Au festival" screenings grouped by day with section glyph+text, regular showtimes without any purchase affordance, related films (up to 6).
- **Attribution:** required TMDB wording and logo, visually subordinate to Tiween branding.
