<objective>
Close gap G-01-1 (blocker): after a short film is created, the redirect to `works/:documentId` crashes with `(e.genres ?? []).map is not a function`.

Root cause, re-verified while planning against the installed `@strapi/content-manager` 5.51.2 (`dist/server/controllers/collection-types.js` lines 390-436 and `dist/server/services/utils/populate.js`):

- The content-manager `findOne` builds its populate with `populateFromQuery(...).populateDeep(Infinity).countRelations()`.
- `getQueryPopulate` reads only the query **filters**, so the `populate` parameter `useWork` sends is ignored.
- Every relation comes back as `{ count: n }`. That covers `genres`, `credits[].person`, `credits[].creditRole`, `cast[].person`, `cast[].character` and `theatreDetails.premiereVenue`. Media and components are still populated.
- `workToFormValues` then calls `.map` on `{ count }` and throws.

The same shape also breaks two other things:

- `ensureTranslationTargets` sees no credited persons, so AR/EN saves would fail with `locale "ar" not found`.
- `workToRuleInput` sees no `director` slug, so the pre-check would wrongly list a missing director.

Fix, plugin-first (CLAUDE.md build rule 1):

- **Server:** a `creative-works` admin route, `GET /creative-works/admin/works/:documentId`. It reads the draft row through the Document Service with an explicit, field-allowlisted populate. It returns the content-manager's exact `{ data, meta }` shape, with `data.status` and `meta.availableLocales` computed by the content-manager's own `document-metadata` service and the output sanitized by its `permission-checker`. The creative-works plugin owns the content type, so the route uses `strapi.documents()` on its own UID, which is R4-compliant.
- **Admin:** `useWork` switches to that route.
- **Defensive layer:** `workToFormValues` tolerates `{ count }` shapes. The page refuses to render a form it would save back with blanks.

The CM relations endpoint alternative was rejected. It needs one request per credit and cast row (2×credits + 2×cast + 1), and it would leave the status and meta logic split across two calls.

Purpose: SC1 / SDATA-02 (admin can create, translate, publish, edit and unpublish a short film) becomes true in a real browser. FR57 (media attachments) is already delivered by 01-07 and 01-13. This plan only keeps `poster`, `backdrop` and `photos` in the editor read, so it adds no FR57 behaviour and does not list it.

Output: admin route + controller + service + boot suite, `useWork` on the new route, tolerant form mapping, edit-page error state, updated jsdom mocks, and a passing Playwright walkthrough (first test) on the isolated E2E stack.
</objective>
